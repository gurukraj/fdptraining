E-Commerce Product Catalog API

Build a RESTful product catalog API for an e-commerce platform that supports full CRUD operations, inventory management with low-stock alerts, flexible search and filtering, soft-delete with restore, and product analytics.

Scenario: An e-commerce startup is building its backend from scratch. The product team needs a catalog service that handles product listings, tracks inventory levels, and provides analytics dashboards showing category breakdowns, price distributions, and most-viewed items. Products must never be hard-deleted; they must only be soft-deleted with the ability to restore.

Technology stack:
- Node.js 20
- Express
- NeDB (embedded document database)
- express-validator
- Jest or Mocha

Functional requirements:

FR-1 Create Product
Add a new product to the catalog with full validation. The name must be 3 to 200 characters, the price must be greater than 0 and have at most 2 decimal places, the SKU must be unique and duplicate SKUs should return HTTP 409, the category must be a valid predefined category, tags must be an array, and imageUrl is optional.

FR-2 List and Search
Retrieve products with pagination, filtering, keyword search, and sorting. The API must support page and limit pagination, filtering by category, priceMin, priceMax, and inStock, search across name and description, and sorting by price, name, or createdAt.

FR-3 Update Product
Apply partial updates to an existing product while re-validating all changed fields. Only provided fields should be updated, the same validation rules from creation should apply, and the API should return HTTP 404 if the product does not exist.

FR-4 Soft Delete and Restore
Mark a product as deleted without removing it. Soft-deleted products must be excluded from standard listings. A restore endpoint must reverse the deletion.

FR-5 Manage Inventory
Adjust stock quantities up or down while preventing negative stock. Stock adjustments must use signed integers (+/-), stock cannot go below 0, and the API should return HTTP 400 for invalid operations. Low-stock products should be flagged, with a default threshold of 10 that can be configured through a query parameter.

FR-6 Product Analytics
Provide analytics for most-viewed products, category breakdown, and price distribution. Most-viewed should return the top N products by viewCount, category breakdown should show count and average price per category, and price distribution should group products into defined price ranges.

Predefined categories:
- Electronics
- Clothing
- Books
- Home & Kitchen
- Sports
- Toys
- Beauty
- Food & Beverages

API endpoints:
- POST /api/products: Create a new product. Success: 201. Errors: 400, 409, 422.
- GET /api/products: List products with search, filter, sort, and pagination. Success: 200. Errors: 400.
- GET /api/products/:id: Get a single product by ID. This endpoint increments viewCount. Success: 200. Errors: 404.
- PUT /api/products/:id: Update a product. Success: 200. Errors: 400, 404, 422.
- DELETE /api/products/:id: Soft-delete a product. Success: 200. Errors: 404.
- POST /api/products/:id/restore: Restore a soft-deleted product. Success: 200. Errors: 404.
- PATCH /api/products/:id/stock: Adjust stock quantity using +/- values. Success: 200. Errors: 400, 404.
- GET /api/products/inventory/low-stock: List products below the stock threshold. Success: 200.
- GET /api/analytics/most-viewed: Get the top products by view count. Success: 200.
- GET /api/analytics/category-breakdown: Get product count and average price per category. Success: 200.
- GET /api/analytics/price-distribution: Get product counts grouped by price range. Success: 200.

Data model:

Product
- _id: string, auto-generated by NeDB
- name: string, required, 3 to 200 characters
- description: string, optional
- price: number, required, greater than 0, maximum 2 decimal places
- sku: string, required, unique
- category: string, required, must be a predefined category
- tags: array, array of strings, default empty
- stockQuantity: integer, default 0, cannot be negative
- imageUrl: string, optional, valid URL format
- viewCount: integer, default 0, incremented on product detail view
- isDeleted: boolean, default false
- createdAt: datetime, auto-set on creation
- updatedAt: datetime, auto-set on creation and update

Category
- Categories are predefined and validation should reject any product whose category does not match one of the predefined values.

Price distribution ranges:
- $0-25
- $25-50
- $50-100
- $100-250
- $250-500
- $500+

Success criteria:
- All 11 endpoints return correct status codes and response structures.
- Product creation validates all field constraints and duplicate SKU values return HTTP 409.
- The listing endpoint supports pagination, all filters, keyword search, and multi-field sorting.
- Soft-deleted products are excluded from listings and search results but can be restored.
- Stock adjustments correctly increment and decrement stock while rejecting operations that would result in negative stock.
- Viewing a product detail increments the viewCount field.
- Analytics endpoints return accurate aggregations over the current non-deleted product set.
- The application starts cleanly and NeDB datastores initialize without manual setup.
- Seed data with at least 10 products across multiple categories can be loaded and queried.
