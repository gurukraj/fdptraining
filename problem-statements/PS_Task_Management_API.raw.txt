Task Management REST API

Build a full-featured task management API with categories, comments, enforced status transitions, role-based access control via request headers, soft-delete cascading, and a complete audit log of all write operations.

Scenario: A development team needs an internal task tracker. The system must enforce a specific workflow (status transitions), support categorization, allow threaded comments on tasks, restrict certain operations to administrators, and maintain a tamper-proof audit trail for compliance purposes.

Technology stack:
- Java 21
- Spring Boot 3.x
- H2 (in-memory)
- Spring Data JPA
- Maven
- JUnit 5, Spring Boot Test

Authentication model:
Authentication is header-based and does not use a login endpoint. Every request must include:
- X-User-Id: identifier for the acting user
- X-User-Role: role of the user, either USER or ADMIN

Requests missing these headers should receive HTTP 401. Operations restricted to ADMIN should return HTTP 403 for USER role.

Functional requirements:

FR-1 Create Task
Create a new task with a title, optional description, priority, and optional category. The title must be 3 to 200 characters, description must be at most 2000 characters, priority must be LOW, MEDIUM, or HIGH with a default of MEDIUM, the status must start as OPEN, and createdBy must be set from the X-User-Id header.

FR-2 View Tasks
Retrieve tasks with pagination, filtering by status, priority, or category, and sorting. The API must support page and size pagination, filtering by status, priority, and category, sorting by createdAt, priority, or title, and exclude soft-deleted tasks.

FR-3 Update Task
Apply partial updates to title, description, priority, or category. Only provided fields should be updated, the API should return HTTP 404 if the task is deleted or does not exist, and status cannot be changed through this endpoint.

FR-4 Status Transitions
Move a task through its workflow using a dedicated status-change endpoint. Only the following transitions are allowed:
- OPEN -> IN_PROGRESS
- IN_PROGRESS -> DONE
- IN_PROGRESS -> OPEN
- DONE -> OPEN
All other transitions must be rejected with HTTP 400 and a descriptive message.

FR-5 Soft Delete Task
Mark a task as deleted. Soft-delete must cascade to its comments, and soft-deleted tasks must be excluded from all listings. DELETE should set a soft-delete flag, associated comments should also be soft-deleted, and soft-deleted tasks should return HTTP 404 on direct lookup.

FR-6 Category Management
Provide CRUD operations for task categories with unique, case-insensitive names. Create and delete operations are restricted to ADMIN; USER requests should get HTTP 403. Delete should be rejected with HTTP 409 if any non-deleted tasks reference the category.

FR-7 Comments
Add and list comments on a task, and delete comments where deletion is ADMIN-only. Comment content is required and must be non-empty, comments must be linked to a task, list operations must return comments for a task sorted by creation time, and delete must be restricted to ADMIN.

FR-8 Audit Log
Automatically log all write operations with entity type, entity ID, action, user, and timestamp. The audit log should cover task, category, and comment create, update, delete, and status change operations; it should be read-only; and it should support filtering by entityType.

API endpoints:
- POST /api/tasks: Create a new task. Success: 201. Errors: 400, 401, 422. Auth: any role.
- GET /api/tasks: List tasks with filters, sorting, and pagination. Success: 200. Errors: 401. Auth: any role.
- GET /api/tasks/{id}: Get a single task by ID. Success: 200. Errors: 401, 404. Auth: any role.
- PUT /api/tasks/{id}: Update task fields except status. Success: 200. Errors: 400, 401, 404, 422. Auth: any role.
- PATCH /api/tasks/{id}/status: Transition task status. Success: 200. Errors: 400, 401, 404. Auth: any role.
- DELETE /api/tasks/{id}: Soft-delete a task and its comments. Success: 200. Errors: 401, 404. Auth: any role.
- POST /api/categories: Create a new category. Success: 201. Errors: 400, 401, 403, 409. Auth: ADMIN only.
- GET /api/categories: List all categories. Success: 200. Errors: 401. Auth: any role.
- PUT /api/categories/{id}: Update a category. Success: 200. Errors: 400, 401, 404. Auth: any role.
- DELETE /api/categories/{id}: Delete a category. Success: 200. Errors: 401, 403, 404, 409. Auth: ADMIN only.
- POST /api/tasks/{id}/comments: Add a comment to a task. Success: 201. Errors: 400, 401, 404. Auth: any role.
- GET /api/tasks/{id}/comments: List comments for a task. Success: 200. Errors: 401, 404. Auth: any role.
- DELETE /api/comments/{id}: Delete a comment. Success: 200. Errors: 401, 403, 404. Auth: ADMIN only.
- GET /api/audit-logs: Query audit log entries. Success: 200. Errors: 401. Auth: any role.

Data model:

Task
- id: long, primary key, auto-generated
- title: string, required, 3 to 200 characters
- description: string, optional, max 2000 characters
- status: enum, OPEN, IN_PROGRESS, DONE, default OPEN
- priority: enum, LOW, MEDIUM, HIGH, default MEDIUM
- category: Category, foreign key, optional
- createdBy: string, set from X-User-Id header
- isDeleted: boolean, default false
- createdAt: datetime, auto-set on creation
- updatedAt: datetime, auto-set on creation and update

Category
- id: long, primary key, auto-generated
- name: string, required, unique case-insensitively
- description: string, optional

Comment
- id: long, primary key, auto-generated
- taskId: long, foreign key to Task, required
- content: string, required, non-empty
- author: string, set from X-User-Id header
- isDeleted: boolean, default false
- createdAt: datetime, auto-set on creation

AuditLog
- id: long, primary key, auto-generated
- entityType: string, TASK, CATEGORY, or COMMENT
- entityId: long, ID of the affected entity
- action: string, CREATE, UPDATE, DELETE, or STATUS_CHANGE
- performedBy: string, user who performed the action
- timestamp: datetime, auto-set when the log entry is created

Relationships:
- A Task optionally belongs to one Category.
- A Task has many Comments.
- AuditLog entries reference entities by type and ID and do not use a foreign key constraint.

Success criteria:
- All 14 endpoints return correct status codes and response structures.
- Header-based authentication enforces HTTP 401 for missing headers and HTTP 403 for unauthorized role.
- Only the four valid status transitions are accepted; all others return HTTP 400.
- Soft-delete on a task cascades to its comments; both are excluded from all listings.
- Category delete is blocked with HTTP 409 when non-deleted tasks reference it.
- Category name uniqueness is enforced case-insensitively.
- Every write operation produces an audit log entry with the correct entity type, action, and user.
- The audit log endpoint supports filtering by entityType.
- The application starts with an H2 in-memory database and auto-creates the schema on launch.
- Seed data with tasks, categories, and comments can be loaded and queried successfully.
