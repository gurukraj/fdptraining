Speckit + GitHub Codespaces Lab Guide for fdptraining

This guide walks through all problem statements in the repository and shows how to implement each one inside GitHub Codespaces using a Speckit-style workflow.

Repository labs

  • Student Grade Calculator: problem-statements/PS_Student_Grade_Calculator.raw.txt
  • Weather Dashboard API: problem-statements/PS_Weather_Dashboard_API.raw.txt
  • E-Commerce Product Catalog: problem-statements/PS_ECommerce_Product_Catalog.raw.txt
  • Task Management API: problem-statements/PS_Task_Management_API.raw.txt

Prerequisites

  • GitHub account
  • GitHub Codespaces access
  • Browser-based VS Code environment
  • The repository opened in Codespaces

Step 1: Open the repository in Codespaces

  1. Open the repository on GitHub.
  2. Click the green Code button.
  3. Select the Codespaces tab.
  4. Click Create codespace on main.
  5. Wait for the Codespace to load.

Step 2: Use a Speckit-style workflow

  1. Read the problem statement.
  2. Extract the functional requirements and endpoints.
  3. Ask your coding assistant to create an implementation plan.
  4. Generate scaffolding and project files.
  5. Implement features one requirement at a time.
  6. Run tests and fix failures.
  7. Refine until the success criteria are met.

Step 3: Create a branch for each lab

git checkout -b lab/student-grade-calculator

Repeat the same pattern for the other labs.

Lab 1: Student Grade Calculator

Goal: Build a FastAPI grading service with validation, scoring, GPA, and reporting.

Source: problem-statements/PS_Student_Grade_Calculator.raw.txt

Suggested prompt:

Implement the student grade calculator described in problem-statements/PS_Student_Grade_Calculator.raw.txt. Create the FastAPI app, SQLite models, validation, endpoints, and tests.

Commands:

cd student-grade-calculator
pip install -r requirements.txt
python seed_database.py
pytest -v
uvicorn app.main:app --reload --port 8000

Verify: duplicate student IDs fail with 409, invalid scores fail with 422, GPA is calculated, and reports return statistics.

Lab 2: Weather Dashboard API

Goal: Build a Flask weather service with current conditions, forecasts, conversion, caching, alerts, favorites, and history.

Source: problem-statements/PS_Weather_Dashboard_API.raw.txt

Suggested prompt:

Implement the weather dashboard API described in problem-statements/PS_Weather_Dashboard_API.raw.txt. Create a Flask app with SQLite-backed caching, mock weather data, conversion endpoints, alert configuration, favorites, history, and tests.

Commands:

cd weather-dashboard-api
pip install -r requirements.txt
python seed_database.py
pytest -v
flask --app app.main run --port 5000

Verify: city and coordinate lookups work, conversions are accurate, cache behavior is correct, and alerts are evaluated properly.

Lab 3: E-Commerce Product Catalog

Goal: Build an Express product catalog API with CRUD, inventory, soft delete, search, filtering, pagination, and analytics.

Source: problem-statements/PS_ECommerce_Product_Catalog.raw.txt

Suggested prompt:

Implement the e-commerce product catalog API described in problem-statements/PS_ECommerce_Product_Catalog.raw.txt. Create an Express app with NeDB, validation, CRUD routes, soft delete and restore, stock adjustments, inventory queries, analytics endpoints, and tests.

Commands:

cd ecommerce-product-catalog
npm install
npm run seed
npm test
npm start

Verify: duplicate SKUs return 409, listings support filters and pagination, soft-delete is reversible, inventory adjustments prevent negative stock, and analytics are accurate.

Lab 4: Task Management API

Goal: Build a Spring Boot task manager with authentication, status transitions, categories, comments, soft delete, and audit logging.

Source: problem-statements/PS_Task_Management_API.raw.txt

Suggested prompt:

Implement the task management API described in problem-statements/PS_Task_Management_API.raw.txt. Create a Spring Boot 3 project with JPA entities, request-header authentication, task status transitions, soft-delete behavior, category management, comments, audit logs, and tests.

Commands:

cd task-management-api
mvn clean compile -DskipTests
mvn spring-boot:run
mvn test

Verify: missing headers cause 401, USER role is blocked from admin-only actions with 403, only valid status transitions are admitted, soft-delete cascades to comments, and audit logs are generated.

Best practices for Codespaces

  • Keep each lab in its own branch.
  • Use small commits after each milestone.
  • Run tests frequently.
  • Use the Ports tab to expose local services if needed.
  • Stop the Codespace when you are done to save compute time.
